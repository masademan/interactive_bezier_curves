[/TAB][H1]Main text writing area:[H1/]
It has the title "Formatted text writer" and this is where all formatted text is written, including this text right here!

You can write text codes and text formatting tags here along with the text you want to show and edit.

Formatting tags have an opening and closing tag to signify what text they're tagging.
The opening tags are written in the form {OPENING_TAG.format("TAG_NAME_HERE")}, and the closing tags are written in the form {CLOSING_TAG.format("TAG_NAME_HERE")}.
So for a "BOLD" tag, the opening and closing tags would be written like {OPENING_TAG.format("BOLD")} and {CLOSING_TAG.format("BOLD")}, with the text you want bolded in between the opening and closing tags.

Text codes are written in the form {TEXT_CODE.format("CODE_NAME_HERE")}, so for a "TAB" code, it would be written like {TEXT_CODE.format("TAB")}.

If there's an error in your formatting, then the preview window will turn red, and if there's a warning in your formatting, the preview window will turn yellow. When there's an error, formatting will stop completely, but if there's a warning, it'll still format everything.
Errors happen when there's an open tag without a closing, or vice versa. And this usually happens with a typo or a missing "/" in the closing tag.
Warnings happen when there's a closing tag between an opening and closing tag that doesn't correspond to either. For example, if there was an opening tag for red text, an opening tag for underlined text, a closing tag for red text, and then a closing tag for underlined text, there'd be an error.
Warning: [RED][UNDERLINED][RED/][UNDERLINED/]
Correct: [RED][UNDERLINED][UNDERLINED/][RED/]

There are 5 buttons at the top of the window which say "Load text", "New text", "Help", "Clear text", and "Copy text".
1. Pressing the "Load text" button opens a popup to ask which .txt file you want to load in. It needs to be a valid .txt file from this program, otherwise it won't load correctly. The only way to guarantee that the .txt works is by saving the text you made and then later loading it in.
2. Pressing the "New text" button clears all the text inputs and removes the link of the current edited text to any .txt file path.
3. Pressing the "Help" button opens a window to explain how to use the entire program. That help guide was written in this very program!
4. Pressing the "Clear text" button clears the text in this window. This action is able to be undone using Ctrl + Z.
5. Pressing the "Copy text" button turns it into a valid Python string, which you can then paste into a triple quoted string. Do note that the copied text doesn't include the quotes, but only the text that goes inside the quotes.


[/TAB][H1]Formatting tag area:[H1/]
[H2]Basics[H2/]
It has the title "Formatted text formatting" and this is where all the formatting tags are defined.

These should be written like writing variables in Python. It should be in this form:
TAG_NAME = { SETTING_NAME: VALUE_TO_SET }

Where "TAG_NAME" is the name you want for that code (rules on naming later), and "{ SETTING_NAME: VALUE_TO_SET }" to be the setting for the text property.

Formatting tags are useful because they let you customize almost any property of text. You can change the font family, size, of styling (bold, italic, etc.), vertical positioning, color, background, etc.

To format text with a formatting tag, you need to use the opening and closing tag. So if you had a tag to turn text red named "RED", you'd write the text like this:
non red text [RED]your red text here[RED/] non red text

There are 3 buttons at the top of the window which say "Clear tags", "Update preview", and "Convert tags and copy"
1. Pressing "Clear tags" clears all the tags in the window, essentially allowing you to restart clean when writing tags.
2. Pressing "Update preview" forces an update on the update window. This is because the tags window doesn't constantly update the preview with changes since you might not be finished with writing a tag.
3. Pressing "Convert tags and copy" takes the tags you wrote, turns it into a dict and copies it to your clipboard. This lets you paste it into a Python file as is.

[H2]Formatting tag rules[H2/]
It's not necessary, but it's recommended to make all the tags in all caps to make them distinct from normal text.
Make sure there aren't any spaces in the tag name, this can lead to ambiguity in the tag name.
Again, these tags should be written like normal variables in Python.

Once you write the tag name, you can have any number of spaces, an equals sign, any number of spaces, and then a dictionary of values to change. Just like in Python, you can write all the parts of the dictionary in one line or split it into multiple lines. The keys of the dictionary should be the names of the tkinter Text attributes that can be edited through tags
Here's a list to all the attributes that can be edited (not clickable):
[HYPERLINK]https://www.tcl-lang.org/man/tcl8.5/TkCmd/text.htm#M26:~:text=non%2Delided%20index.-,TAGS,-The%20first%20form[HYPERLINK/]

You don't have to necessarily use quote marks to signify something is a string in the dictionary. If it's made up of numbers, it's assumed to be a float or integer (depending on whether or not there's a decimal point). If it's "True" or "False" (case insensitive), it'll assume it's a boolean. If it has parentheses, it's assumed to be a tuple. Otherwise, it's a string. You can explicitly make something a string by using quotes, double or single. If using strings, the definition of strings works the same as Python strings. Triple quotes, single quote in double quoted strings, double quote in single quoted strings, backslashes to split a string along different lines, and escape characters (\\, \n, \t, etc.) work.


[/TAB][H1]Text code area:[H1/]
[H2]Basics[H2/]
It has the title "Formatted text codes" and this is where all the text codes are defined.

These should be written like writing variables in Python. It should be in this form:
CODE_NAME = "[TEXT_HERE]"

Where "CODE_NAME" is the name you want for that code (rules on naming later), and "[TEXT_HERE]" to be the text you want to the text codes

The reason why text codes are useful are that you can make a code that's later editable, like a TAB code, that you can later adjust how much spacing it adds, or it can be used to shorten extremely repetitive text. Like, if you wanted to write "(x[TRUE_SUBSCRIPT]i[TRUE_SUBSCRIPT/], y[TRUE_SUBSCRIPT]i[TRUE_SUBSCRIPT/])", you'd have to constantly write:
(x[SUBSCRIPT]i[SUBSCRIPT/], y[SUBSCRIPT]i[SUBSCRIPT/])
Which is extremely hard to read and repetitive, so you can write a text code like:
COORD_I = (x[SUBSCRIPT]i[SUBSCRIPT/], y[SUBSCRIPT]i[SUBSCRIPT/])

So instead of writing the mess of text from earlier, you could just write "[/COORD_I]" to get "[/TRUE_COORD_I]"
This makes writing formatted text much easier to read and navigate.

There are 3 buttons at the top of the window which say "Clear codes", "Update preview", and "Convert codes and copy"
1. Pressing "Clear codes" clears all the codes in the window, essentially allowing you to restart clean when writing codes.
2. Pressing "Update preview" forces an update on the update window. This is because the tags window doesn't constantly update the preview with changes since you might not be finished with writing a tag.
3. Pressing "Convert codes and copy" takes the tags you wrote, turns it into a dict and copies it to your clipboard. This lets you paste it into a Python file as is.

[H2]Text code rules[H2/]
It's not necessary, but it's recommended to make all the codes in all caps to make them distinct from normal text.
Make sure there aren't any spaces in the text code name, this can lead to ambiguity in the text code name.
Again, these text codes should be written like normal variables in Python.

Once you write the text code name, you can have any number of spaces, an equals sign, any number of spaces, and then an opening single or double quote followed by your text and the accompanying closing quote.
Again, like Python, if you want double quotes in the text code, you can use single quotes for the opening and closing quotes, and for single quotes in the text code, use double quotes.
But also like in Python, you can use \" or \' to make sure that the quote is rendered properly and avoids bugs.

Finally, if the text code is getting too long, you can make a break the string into 2 lines with a backslash.
This doesn't add a newline character, and the code interpretes the string as unbroken. Again, spaces between the closing quote and backslash don't matter, like in regular Python.
Example:
LONG_THING = "This sentence is pretty long" \
", so let's break it into 2 lines"

The code would interpret this as "This sentence is pretty long, so let's break it into 2 lines" with no newline characters added.

Also like regular Python strings, you can also have escape codes, like your usual \t, \n, \\, etc.


[/TAB][H1]Text preview area:[H1/]
It has the title "Formatted text preview" and this is where the preview of the formatting appears.

Whatever you type in the "Formatted text writer" area is shown here with the formatting tags and text codes changing the text accordingly.

There is more info in the section about the text writer window in the "Main text writing area" chapter, but when there's an error with the formatting tags, the background in this window turns red. And when there's a warning, it turns yellow.

There are 2 checkboxes and 2 button at the top of the window that says "Do formatting", "Do text codes", and "Save text" and "Save text as"
1. The "Do formatting" checkbox controls whether the formatting tags are used or not. If they are used, you don't see them in the preview and the text gets formatted. If they aren't used, then the tags are just placed into the preview without the formatting on the enclosed text.
2. The "Do text codes" checkbox works similarly to the "Do formatting" one, but instead of formatting text, it'll be replaced by its corresponding string. So if it's on, then it'll replace the text codes, otherwise, you'll just see the text codes in the preview.
3. Pressing the "Save text" button saves the guide you made in a .txt file. If the text doesn't have a specified file linked to it, it'll prompt you to give it a file name. Once it has a linked file, pressing the save button uses the same file name.
4. Pressing the "Save text as" button works like the "Save text" button, but instead of it using the same file name once it's linked, it'll always prompt you for the file name. This can allow you to copy a text save or replace other files. But doing this will change the linked file that the current edited text is one
